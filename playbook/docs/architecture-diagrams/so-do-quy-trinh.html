Định vị & ràng buộc

Strategy plane · vì sao tồn tại

Chốt đối tượng, lời hứa giá trị, mô hình kinh doanh, giới hạn ngân sách/thời gian. Đây là tầng quyết định mọi thứ phía sau, không được bỏ qua để nhảy vào kỹ thuật.

Phạm vi & mô hình nội dung

Scope plane · cái gì

Định nghĩa các loại thực thể (entity), thuộc tính, quan hệ; chốt SEO/GEO yêu cầu ở mức khái niệm. Đây là nguồn sự thật mà code và schema sẽ bám theo.

Cowork→ CONTENT_MODEL.md
2

Kiến trúc hệ thống

C4 · Context → Container

Vẽ hệ thống ở 4 độ phân giải: bối cảnh, các khối hạ tầng, thành phần, code. Mục tiêu là một bức tranh mà người mới nhìn vào hiểu được luồng dữ liệu.

Cowork→ SAD + sơ đồ C4
3

Chốt Stack — bằng ADR

Architecture Decision Record

Mỗi lựa chọn công nghệ phải ghi: bối cảnh, phương án xem xét, phương án bị loại, lý do. Đây là vắc-xin chống "đổi stack mất trí nhớ" — lỗ hổng số 1 của dự án hiện tại.

Cowork→ ADR-0001…000n
4

Luật hệ thống bất biến

Constraints R1…Rn

Các ràng buộc cứng mà Code không được phá: ví dụ chỉ chạy edge runtime, cấm Node built-in, mọi truy vấn DB phải prepared statement, ref_id luôn là slug thuần. Code đọc file này như luật.

Cowork→ CONSTRAINTS.md
5

Cấu trúc IA & schema dữ liệu

Structure plane · tổ chức thông tin

Bản đồ URL, taxonomy, canonical, và schema D1 đầy đủ (cột, kiểu, index, junction table). Giải quyết trùng lặp/ăn thịt nội dung trước khi viết một dòng giao diện.

Cowork + Code→ URL map + DB schema
6

Khung trang + Binding map

Skeleton plane · khung trước, đẹp sau

Wireframe các trang lõi và ánh xạ mỗi vùng giao diện ↔ field dữ liệu nào. Đây là tài liệu khiến Design và Code không phải đoán.

Cowork→ Component-to-Data map
⛔
Luật cứng: chưa có Binding map → cấm bước thiết kếĐảo thứ tự ở đây là nguyên nhân làm lại nhiều ngày. Bề mặt không bao giờ đi trước cấu trúc.
7

Bề mặt — thiết kế giao diện

Surface plane · một nguồn token duy nhất

Vẽ mockup từ binding map, xuất HTML + một bộ design token DUY NHẤT (màu, font, radius, spacing). Không cho phép hai file design system song song tồn tại.

Claude / Open Design→ mockup + DESIGN_TOKENS

8

Thực thi có cổng kiểm soát

Spec-driven · build & ship

Code thực thi theo prompt, commit, deploy. Sau khi xong qua Cổng QA2 (đối chiếu với SPEC + CONSTRAINTS) rồi mới merge. Bạn quyết định, Cowork giám sát, Code làm.

Claude Code→ PR + QA2 checklist
Đọc sơ đồ Trục dọc đi từ trừu tượng (vì sao) xuống cụ thể (code). Hai dấu cổng terracotta/xanh là điểm dừng bắt buộc. Lặp lại được cho mọi website sau: chỉ thay nội dung trong các artifact, giữ nguyên thứ tự và các cổng.
